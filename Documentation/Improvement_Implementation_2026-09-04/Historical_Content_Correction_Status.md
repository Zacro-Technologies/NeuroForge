# Historical content correction policy — updated 2026-09-05

`Sources/TrainingEngine/NFContentCorrectionPolicy.swift` now exposes `audit(NFHistoricalContentCorrectionInput)` alongside the original source-compatible `findings` API. The audit is pure: it reads immutable record fields and an optional authenticated exact original snapshot, and returns recommendations and explicit unresolved reasons. It never writes an attempt, resets a response, changes confidence, creates an attempt, or adjusts XP.

The integrated persistence adapter appends correction records with timestamps, reconciles active policy membership and disposition supersession, exposes notices, and applies scope exclusions to derived summaries. The pure audit remains separate from persistence. A proposed correction alone is not proof that an arbitrary historical store has been migrated.

## DATA-023 contract

Each recommendation records original attempt ID, rule ID, `HistoricalContentCorrectionsV2`, disposition, original-result SHA-256 digest, optional corrected deterministic credit, corrected scorer version 8 and per-rule contract revision, excluded evidence scopes, rationale, and stable idempotency key. The digest covers exact original response bytes and retained key/result/timestamp/confidence fields, plus original result payload bytes when available. The idempotency key includes attempt, rule, policy, and digest. Additional reports or provenance findings do not change the key of an already established correction. The persistence adapter stamps `createdAt` when appending; wall-clock time is deliberately absent from the pure decision.

Exact snapshots must be explicitly verified as captured at attempt time or authenticated exact original descriptor reproductions. Item ID, template ID, prompt, and any retained generator version must match the record. A regenerated current item, a matching seed alone, or an unverified snapshot cannot establish grading authority. A shipped `nf.fallback.<lab>.<pool>.v1–3` namespace plus pre-8 scoring can identify the affected legacy edition when generator version was not separately stored. Scorer age alone does not establish a custom item's lineage.

## Related content authority

Exact known retrieval-cycle steps or the exact generic source-filter pseudocode limit the objective to learning-method practice. Their historical task accuracy remains available, while subject proficiency, band and retention claims are excluded. This does not retrofit subject derivation or actual code tracing to a workflow exercise.

Exact original visible solution markers are recognized for the even-product counterexample, odd-sum completed proof, first invalid division, independent experiment design, and compensation decomposition. Current role filtering is respected: a tagged post-response or optional representation that was not independently rendered does not become a proven pre-response leak. Confirmed historical exposure can separately establish assisted practice. Assisted work preserves accuracy and effort while excluding independent proficiency, clean speed, calibration and retention. For a known affected legacy family with no original presentation, those claims are precautionarily excluded and the uncertainty is explicit; no actual hint event is invented.

Translated original prompts not matching the narrowly reviewed rule, unknown interval delimiters/units, unavailable legacy option text, absent accepted-state sets, unknown function domains, and unreviewed prose remain unresolved. These are not silently converted into incorrect answers. The existing release/content incident ledger still needs editorial triage and per-contract supersession where the specification requires human review.
