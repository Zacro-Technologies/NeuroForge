# Scratchpad recovery and rendering bounds — 5 September 2026

This is a bounded DATA-020 follow-up authored after the successful 784-test Mac run at 01:49:57. The new code parses and whitespace checks pass; its tests await the next root-owned build. It does not claim general media recovery or CORE-004 background rendering completion.

`NFScratchpadInspection` retains the exact original stored string and separates readable supported payloads from malformed, future and oversized envelopes. The existing version1 prefix and Codable notes/drawingData fields remain unchanged; legacy plain text remains readable. Encoded length is bounded before Base64 allocation, the decoded JSON envelope is capped at8MiB and drawing data at4MiB. Unknown encoded versions are not displayed as learner notes.

The live scratchpad opens unavailable work in a read-only recovery view; automatic persistence, Clear and on-disappear do not rewrite it as an empty drawing. The explicit recovery exporter writes the exact original UTF-8 bytes to a text file. For newly edited oversized work, the prior stored value remains unchanged, the screen explicitly says the edit is not saved, and Done/swipe dismissal are blocked while the learner reduces or exports the current content. Export alone does not claim a checkpoint save.

On iOS, drawing bytes pass the byte limit before PencilKit decoding. Invalid drawings return no drawing rather than a blank replacement. Geometry must be finite, remain within absolute coordinate1,000,000 and span100,000; previews then downscale to at most1,024 pixels on either dimension, with downward rounding at the boundary. The completed-history path uses the same inspector and geometry policy. Unavailable previews expose original recovery export instead of requesting a bitmap from arbitrary saved bounds. Original source data is never replaced by the preview.

Six cross-platform `ScratchpadSafetyTests` methods in LocalLearningLifecycleTests cover supported/legacy preservation, malformed/future read-only refusal, small synthetic encoded/decoded/drawing size boundaries, finite/oversized preview geometry, exact recovery file bytes, and actual local session reload plus portable backup preservation. One additional iOS-only method constructs real PencilKit strokes, verifies a normal bounded raster, and rejects corrupt/huge-span drawing bytes without rasterizing the unsafe drawing. No giant memory allocation is used for size tests.

The new implementation touches ScratchpadView and the narrow completed-scratchpad/preview portion of ProgressDashboardView. It does not alter SwiftData schemas, response scoring, evidence authority or protected answer export policy. General images, asynchronous decode/rendering, current iOS execution and physical Pencil/accessibility validation remain separate acceptance work.
