# Generated unscored outcomes through the archive worker

This is a delta atop the integrated generated Submit and Next/End packages. It modifies five existing files and adds no model columns, portable schema fields, localization keys, or new project files.

## Production caller and transaction boundaries

- Generated Skip's actual menu action awaits `skipAsync`; the hint button awaits `requestHintAsync`, which delegates exhausted-ladder requests to `revealSolutionAsync`. Intermediate hint persistence retains its existing synchronous path and is a separate migration slice.
- `NFSessionLifecycleCoordinator.commitUnscoredAsync` owns receipt-first reconciliation and the same legal item/confidence/feedback phases as the existing unscored coordinator. It never invents a scoring result. The shared gate retains a busy UI and excludes storage waits from solving time.
- Preparation freezes the exact typed response, existing attempt/run identity, unscored outcome, and a single worked-solution assistance event. The actor durably saves that prepared draft before retaining an immutable question snapshot.
- A new typed generated-attempt operation validates the exact private predecessor digest, owner, version/response contract, current attempt, document-practice authority, skipped/revealed marker, zero credit/evidence, nil confidence, timing, source provenance, and all retained sidecars. The scored branch retains its distinct score and non-unscored guards.
- `prepareSkippedExercise` is the original synchronous skipped-record builder extracted unchanged. Both existing ordinary callers and the new generated adapter share all original fields. The temporary `AttemptRecord`, ModelContext, final core insertion and core conflict comparison remain on MainActor; only immutable values cross to the existing storage actor.
- Snapshot acknowledgement is verified before any core insertion; the writer generation is rechecked after suspension. A conflicting original is retained and a typed zero-evidence diagnostic is written through the actor.
- Unscored feedback uses the existing typed pending-publication acknowledgement/repair path. An accepted rename updates the repository/revision but cannot display a worked solution before verification. Repair publishes the frozen outcome only once and never appends correctness. Pause interruption metadata remains owned by the current presentation.
- Successful Skip then awaits the already-integrated `nextAsync`. Cancellation after committed unscored feedback retains that feedback and skips automatic advance. Cold Retry acknowledges the exact saved outcome without inventing a fresh question; explicit Next/End chooses the subsequent transition.
- Same-slot command replays and cold receipt-before-feedback recovery use immutable original receipts. Pending verification or advance prevents a competing unscored action from changing phase or overwriting accepted state.
