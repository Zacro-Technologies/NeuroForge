## Production path and authority

- `AppStore.reviewedPracticeRequest` constructs the actual proposed exact-bank recipe without reading `todayPlan` (that accessor can write a daily plan). `reviewedStartingPreview` captures immutable raw/effective evidence and read-only remaining rotation positions, evaluates the actual admitted candidates on a cancellable detached task, then rejects a stale local archive revision.
- `NFEditorialPrelaunchPolicy` materializes exact bank descriptors with the same request settings and current module policy flags. Full admission digest, item identity, field, activity template slug, prerequisites, timing compatibility, current quarantine, prior exposure and semantic uniqueness all constrain the options. Unknown/no registry and temporary feasibility shortages remain explicit. It does not reserve a future item, write a plan, or award proficiency.
- Each reviewed family offers only its actually feasible B1–B4 choices. An Automatic option runs the existing `NFEditorialLiveController` with no explicit band, preserving `coldStartDefault`, `recentPracticeTarget`, or `refreshProbe`. Explicit choices retain `userRequested`. The exact displayed reasoning-step range and remaining unique count come from the admitted demand records; these are editorial demands, not measured learner levels.
- `beginDefaultCatalogSession` forwards `editorialStartingBand` and `editorialStartingFamilyScope`. New nonnil family/catalog scope distinguishes automatic reviewed launches (nil explicit band) from old nil-band + nil-scope callers. New reviewed routes use the actual bank with `mechanicID:nil`, never relabel the old mechanic-filtered seed recipe as an exact-bank delivery.
- Typed opt-in module recipes are matched to explicit activity IDs only after full contract validation (spatial, retrieval assets, linked science/transfer and graph). Legacy subvariants use a finite allowlist; malformed typed metadata cannot fall back to a legacy slug. This mapping does not expand the independent-evidence protocol beyond its supported response families.
- New `NFEditorialSessionPin` schema 3 carries `NFEditorialCatalogScope` (schema1, catalog version, activity ID, field). Every admission lookup at Next/Replace rechecks the same activity slug and field. Existing schema1 single-family and schema2 mixed pins keep their behavior and bytes; unsupported future catalog scope is recovery-only. No accepted receipt target or recipe is rewritten.
- Initial reviewed catalog acceptance recomputes the hard-feasible unique count at the selected target under the existing transaction/CAS. It refuses an unavailable requested count. The UI offers an explicit smaller count, never silently shrinks it. This is a feasibility check, not reservation of future slots; subsequent quarantine/exposure can still require an honest unavailable boundary.
- General Lab detail preserves Automatic mixed practice. An explicit family choice is labeled as focusing that session on the shown reviewed family. Catalog activity choice hard-pins the chosen activity. Timing remains separate. The native starting-challenge Menu places a minimum 44-point frame inside its actual label, uses checkmarked commands, and exposes the current selection as its accessibility value. The existing public graph-construction launch remains unchanged.
- The released admission registry remains empty. No reviewed choices appear and legacy nil-band catalog controls remain available. Nothing here signs off or enables the shipped unsigned bank.

## Limits retained honestly

- No external editorial or empirical validation is fabricated. The actual admitted registry remains an external release gate.
- Preview captures the current in-process/effective history and checks archive revision. It is advisory; final acceptance remains authoritative for all other concurrent changes.
- Protected-check suggestions remain governed by existing controller input authority, not guessed by this screen. No legacy evidence is backfilled.
- The existing mixed controller's deferred per-family state and global support window are unchanged; scope-constrained activities intentionally do not promise cross-family variety.
