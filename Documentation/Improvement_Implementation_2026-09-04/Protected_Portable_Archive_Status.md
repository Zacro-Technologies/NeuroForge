# Protected portable archive correction

The full archive previously copied protected attempts' exact keys, binary correctness, deterministic credit, error codes and evidence weight. Its legacy checkpoints also copied per-item results/credits and inferred reflection fields. The device-local journal had a separate export filter, which did not protect these other archive surfaces.

`NFDataExportService.protectedPortableData` now applies explicit per-field allowlists to protected attempt and legacy checkpoint rows before the public file is written. It retains stable identities, authentic learner response/confidence/time, scratchpad data and evaluator references. It exports an opaque versioned `protectedReceipt`; it omits exact keys, per-item scores, inferred error fields and evidence weight. Protected report diagnostics and nested request/checkpoint evaluators are removed. Protected question bodies in generated/saved sets are withheld; ordinary practice retains its content. Summary and source-review CSV files do not expose protected scores. Source-review CSV preserves the learner's own response/confidence with a protected-response-saved outcome.

The same allowlists run during v14–18 restore, after sequential compatibility defaults and before generic Codable reconstruction. An old archive cannot restore hidden evaluator fields by omitting the new marker or by nesting an evaluator in a protected run. Legacy model adapters receive neutral mandatory scalar placeholders, zero evidence weight and `protected_evaluator_unavailable`; these values are explicitly unavailable rather than an incorrect result. Protected checkpoints retain their draft and notes, but a recovery stop reason prevents seed-only writable continuation. The restore preview explains that the verified evaluator is required. Original live records are never edited by export.

The identity-only round-trip validator still reads the public redacted file directly. The restoring decoder is responsible for interpreting the opaque receipt and supplying legacy model placeholders. The optional portable receipt fields default to nil for prior archive versions; no SwiftData model/schema or production signing key was changed by this work.

Applicable requirements are DATA-003, DATA-008, DATA-010 and MIG-006. DATA-007 concerns scratchpad portability; notes/drawings are retained by this change. A verified-evaluator restoration adapter is not implemented here: protected portable recovery remains unavailable rather than reconstructing restricted grades or granting a writer. No cryptographic secrecy against examination of the offline executable is claimed.

A subsequent root-owned defense validates opaque privateStudyRuns as exactly NFPrivateStudyMetadata or NFGeneratedPracticeDraft, verifies outer payload identity/schema and ordinary authority, and re-encodes typed values before import/export. Unknown/protected incoming payloads are rejected. Existing invalid payloads remain on disk and are omitted from portable content with unavailablePrivateRunIDs listed. This closes the base64 channel that a view-only validity filter could not protect.
