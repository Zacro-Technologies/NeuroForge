# Reservation and actual exposure implementation

The source now implements atomic acceptance and eligibility-aware holes for fixed blocks and for new ordinary mixed `adaptiveItem` delivery. The latter accepts one exact-bank question per transaction. It also contains a pure consumed-position policy and actual-presentation ledger. This does not certify complete reviewed band selection.

## Durable fixed launch

`NFOfflineQuestionRotation.prepareReservation` computes an exact plan and replacement cursor ledger without changing its source. It retains the existing algorithm, profile/lab/lane/bank-version namespace, epoch order, boundary exclusions, reservation ordinal and stable question IDs. The old `reserve` API remains a compatibility/test adapter; `AppStore.beginSession` no longer uses it to write UserDefaults.

`NFLocalSessionRepository.prepareFixedLaunch` takes a stable command ID and a read-only legacy snapshot only when its local cursor authority has not yet been initialized. `acceptFixedLaunch` preflights the exact mixed block against quarantine and run-wide semantic exclusions, then publishes the replacement consumption ledger, full eligible plan, launch receipt, run identity, first slot/attempt identity, current snapshot and selection decision in one atomic file replacement. Future exercises are generated transiently for capacity checks; only the first snapshot is retained at launch. Accepted fixed-block positions remain reserved when the learner abandons the run. Failed preparation/publication consumes nothing and leaves the acknowledged predecessor intact.

The initial snapshot is built from shared empty-response construction, without a throwaway runtime or duplicate writer claim. A fresh accepted launch begins with zero interruptions and no presentation time. A later cold resume still enters paused with an unknown interruption gap. Repair origins, semantic exclusions, locale and quarantine constraints are supplied before acceptance, so the runtime cannot change the accepted configuration by adding them afterward.

The optional embedded cursor ledger and one-time migration receipt preserve the actual old ledger, including prior-epoch boundary exclusions. After bootstrap, new launches read and write the local authority; UserDefaults is no longer consulted for new launches. The production legacy store holds its process lock through first publication and the proposal is rejected if the source changed before that boundary. An accepted command replays the original run and snapshot; conflicting command configuration fails. Deleting linked work leaves consumed cursor state and a deleted-command tombstone, so an old launch command cannot resurrect deleted work. Portable export strips cursor authority, migration receipts and fixed-launch commands; imported history does not become a live cursor authority on another device.

All local replacements now use a transaction revision, a process lock and an advisory file lock. Independent repository instances cannot publish two proposals from the same predecessor: the stale proposal fails and must be re-prepared from validated current state. Files that disappear after acknowledgement are not silently recreated. Bounded reads reject files exceeding the archive limit, including files that grow after repository initialization. Startup and pre-launch refresh share duplicate-ID, snapshot, selection-ledger, rotation-version and receipt-reference validation. Invalid checkpoints retain their recovery state; corrupt authority cannot silently become an empty cursor.

## Ordinary decisions and exposure

`NFSelectionReservationLedger` stores scope/version pins, consumed positions, decision IDs, ordered slots with stable attempt IDs, semantic exclusions, exact snapshot payload/digest, outcomes and separate actual-presentation records. Snapshots are deduplicated within privacy/profile scope. The pure policy supports all-or-nothing fixed blocks or one adaptive item, filters ineligible/protected/consumed/semantic-repeat candidates before ranking, never consumes advisory prewarm, preserves consumption after abandonment/replacement, and replays an accepted decision after a stale retry.

`NFLocalReservationBridge` publishes the current ordinary receipt with each matching checkpoint. A captured item starts reserved; only the visible callback records actual exposure. Repeated rendering retains its original event and time. An acknowledged attempt completes the slot once. Prepared skip/reveal alone is intent; advancement after acknowledgement completes the predecessor with a distinct skipped or revealed disposition. Ending a run does not create an incorrect score for an unanswered slot. Personal/source work and protected forms cannot enter this ordinary ledger.

The bridge uses two explicit recipes:

- `legacy-plan-occurrence.v1` retains the exact mixed plan's epoch and permutation position within this run. It checks catalog ordinal mapping and captured descriptor seed before attributing a snapshot to a plan. Filtered activities cannot impersonate mixed-bank question IDs. All plan positions remain reserved while only captured current snapshots become materialized slots.
- `snapshot-slot.v1` records a captured position within this run and makes no global novelty claim. An old resumed Q3 initially records only its actual snapshot at logical question 3/path ordinal 0. It does not invent Q1/Q2 exposure, timing or global consumption.

`NFLegacyRotationMigrationBridge.seedLegacyScope` imports the actual old cursor into a compact completed-epoch/current-prefix range and preserves any sparse consumed positions in the source. A missing new ledger is not proof of an empty old cursor, and catalog ordinal is not permutation position.

## Corrected duration and fixed-slot behavior

A minute-only focused request no longer reserves inventory before its duration/count choice. Closing that choice consumes nothing. Accepting five questions re-enters canonical launch with exactly five reserved positions and retained provenance; a failed launch restores the choice for retry.

An exact fixed descriptor cannot trigger a different-seed fallback. If a later fixed slot is excluded or unavailable, the runtime reports unavailability and preserves its acknowledged predecessor, rather than silently changing the fixed plan or switching reservation recipes.

## Remaining boundaries

The fixed mixed driver now keeps the legacy cursor as a compact consumed prefix plus optional `consumedEpochOrdinals` beyond the first unconsumed position. Selection scans the unchanged original permutation, leaves unavailable descriptors unconsumed, and compresses the prefix only after holes are filled. No new epoch starts while any position remains unconsumed. If the remaining feasible inventory cannot fill the requested block, acceptance fails explicitly with no partial run or cursor write. A later reinstatement can deliver the original hole identity; its stable ordinal need not exceed the previous delivered ordinal. The original provisional-input digest and final canonical configuration digest are retained separately, allowing both retries to return the same saved block. Already accepted future slots are not amended by later exclusions: continuation becomes unavailable with the predecessor preserved. A separately accepted fixed-block remaining-work amendment and the reviewed adaptive next-item controller remain open. The ordinary mixed Replace transaction added below does not amend fixed blocks.

Selected-activity lanes still use legacy reservations to vary their launch seed; those bank IDs are not claimed to be the delivered mechanic-filtered questions. Production reviewed B1–B4 inventory, next-band feasibility/control integration, durable demand-override UI, protected-form exposure protocols and approved edition transition mappings remain separate work. A new generator/catalog cannot silently rewrite a frozen current snapshot; continuation into changed future content can remain unavailable until a compatible continuation policy is supplied.

File locking/CAS covers participating current-version local repositories. It does not establish cross-device no-repeat, shared writable drafts, or safe concurrent use of an older binary that continues writing the obsolete UserDefaults authority. Those are not supported handoffs. A stale independent writer fails closed; its unsaved editor remains separate from the newly acknowledged state and requires explicit recovery.

## New ordinary mixed one-item delivery — current source, execution pending

New mixed practice launched through `AppStore.beginSession` (focused or Today, no selected mechanic/subtype, protected assessment, transfer brief, or retention target) defaults to the optional versioned `NFOrdinaryDeliveryPin(strategy: .adaptiveItem)`. Existing requests with a nil pin keep their old delivery; explicitly requested `.fixedBlock` retains the original full-block contract. The requested question count stays fixed. An unresolved minute-only launch keeps its delivery preference but consumes no position; the explicit five-question alternative enters the canonical launch and accepts only its first position.

`prepareAdaptiveItem` computes one eligible exact-bank descriptor using the existing profile/lab/lane/bank permutation and compact prefix-plus-holes authority. It retains stable decision, slot and attempt IDs, canonical configuration digest, original epoch position and current eligibility revision. No speculative preparation mutates or exposes anything. `acceptAdaptiveItem` checks the archive/run revision and original predecessor under the same nonblocking publication lock, verifies current quarantine, re-materializes the complete exact contract from the frozen request, authenticates the carried history and timing transition, and re-derives the exact one-position consumption delta. The atomic replacement contains the run checkpoint, consumption, migration where required, receipt, ordered slot, exact snapshot and selection decision. Same accepted command replay returns the durable run; stale proposals must be re-prepared. Edited prompt/key content under the same descriptor seed, extra consumed positions and changed prior results are rejected before publication.

The Universal Next path prepares this transaction only for pinned adaptive delivery and accepts only an actual next item; a finite shortage or budget boundary retains the acknowledged feedback/summary without consuming a speculative candidate. Prior answered/skipped/revealed slots and their snapshot contracts remain in the ledger. Actual presentation continues through a separate idempotent visible callback. Abandonment leaves an accepted unpresented position consumed. Export omits the new device authority receipts, and imported adaptive runs remain recovery-only. Deletion removes linked receipts/snapshots while retaining anonymous consumption and a deleted-run command tombstone. Future delivery versions retain their original local payload and cannot resume writable selection.

## Mixed ordinary Replace — implemented source, current verification pending

The coordinator confirmed the corrected pre-Replace baseline: **852 app tests passed**. The preceding scoped one-item run passed all **34 focused rotation integration tests** and **eight reservation bridge tests**. This is the verified baseline, not execution evidence for the following additions.

The guarded Universal “Replace with another question” action applies only to an uncommitted current ordinary mixed adaptive item. It first saves the exact draft, then calls `AppStore.prepareAdaptiveReplacement` and `acceptAdaptiveItem`. The transaction accepts a new decision, slot, attempt and exact-bank position at the same promised question index. It retains the original position as consumed and the old slot as replaced. The complete retained path remains available to semantic exclusion and exact snapshot lookup. Actual display is still a separate acknowledgment; preparation or replacement never fabricates an exposure for a hidden item.

Schema-2 adaptive receipts explicitly pin operation and decision ordinal, because a replacement increments the decision ordinal without incrementing the question number. Existing schema-1 receipts retain their original bytes/fields and infer only their former launch/next semantics. New continuation retains original request, bank, generator/scorer and presentation pins. The append-only `NFLocalRetiredOrdinaryDraft` records `itemReplacedByUser`, the exact old unsubmitted response/confidence/scratchpad/assistance/timing checkpoint and its canonical digest, timestamp, original attempt/slot and replacement decision. Its exercise is deduplicated in the existing authenticated ledger snapshot. It creates no AttemptRecord, score, incorrect outcome, learning observation or XP.

Preparation identifies retry by operation plus exact predecessor before allocating a new decision ordinal. Acceptance revalidates the current predecessor, digest, complete canonical materialization, current eligibility, history/timing carry, exact one-position delta and archive/run revisions under the existing nonblocking lock. A repeated accepted command returns the current durable checkpoint, including edits made after acknowledgment. Changed original drafts, forged history, committed answers and generic stale-slot rewinds fail. A finite eligibility shortage or failed publication retains the original editor and consumption unchanged. Fixed and nil-pinned legacy requests keep their existing behavior.

Replacement carries prior scratchpad and accumulated results unchanged, adds only the old item’s known solving duration to cumulative practice time, and preserves already measured sitting time once. The new item starts with zero solving time and fresh confidence/help state. No time elapses for a prepared replacement until actual presentation acknowledgment. Cold reopen restores the exact current item paused and retains the whole replaced path. Unknown receipt operations or retired-record versions place the run in read-only recovery; generic saves cannot restore write authority. Retired records are never automatically reattached as the current response.

Portable exports retain readable ordinary retired drafts and exact snapshots but strip local cursor and adaptive receipt authority. Import retains the original owner and recovery-only status, verifies retired snapshot/digest/ledger links, and supports exact re-import without duplicating the retired draft. Deleting any path attempt, including a retired unsubmitted attempt, removes the entire linked run, slots, decisions, exposures, retired payloads and unshared snapshots; cursor consumption and the deleted-command tombstone remain.
