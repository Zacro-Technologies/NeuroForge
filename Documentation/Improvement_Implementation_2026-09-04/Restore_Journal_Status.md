# Restore journal and startup boundary

The repository now contains an immutable private restore-plan journal, exact raw before/after snapshots, bounded cross-account discovery, a kernel-backed process lease held across the entire launch, and a startup gate before identity migration, ModelContainer opening and AppStore initialization. Whole-device purge includes the global `NeuroForge/RestoreTransactions` directory. These additions passed the integrated Mac application build and all 19 journal/startup/lease tests as part of the 945/945 passing suite. The iOS application also builds; installed full-app restore/relaunch remains unverified.

Journal acceptance writes and verifies the complete plan and descriptor before atomically publishing acceptance. File writes and the containing directory are flushed. Before-images retain protected/private local data and do not enter portable exports. Payload loading requires the exact installation owner and namespace; cross-account discovery exposes status metadata only. Each database and each file is reconciled against exact accepted before/after states. Unexpected third states stop recovery. Verified completion requires observed postimages; invalidation precedes removal of recovery bytes and leaves a small command tombstone to prevent replay.

Startup checks all namespaces because the local-derived store and managed source surfaces are shared. Unknown, corrupt, partial, unfinished or invalidated-but-not-cleaned work blocks normal startup. Completed receipts are checked against the intact accepted plan. The ordinary no-journal path creates no storage. The recovery view exposes no source names, answers, raw payloads or account identifiers.

There are 19 new journal/startup and process-lease test methods, including acceptance/progress/cleanup write boundaries, lost acknowledgements, mixed database states, third-state conflicts, wrong account and version rejection, symbolic link and named pipe rejection, private file permissions, process file locking, completed artifact integrity and full-device artifact removal. All 19 passed in the integrated Mac XCTest run. The exact process-lease implementation separately passed a real two-process native Swift check: the competing process was blocked while the first was alive, then acquired after the first exited. See Native_Store_Lease_Process_Probe.json.

Still required for MIG-007: a staged request and reviewed destination revision, plan compilation in a disposable store without AppStore initializer side effects, complete writer exclusion, controlled restart with CloudKit disabled before application, live deterministic domain application and startup forward recovery, linked source/attempt artifact invalidation, UI progress and result integration, and authentic multi-domain process-interruption tests. The current legacy restore path still uses in-process compensation. The journal/startup additions do not make that path crash-atomic, and no full restore completion claim is made.
