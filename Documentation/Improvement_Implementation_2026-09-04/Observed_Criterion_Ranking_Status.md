New ObservedCriterionPreferenceV1 derives component IDs from the supported scorer contract: neutral response for numeric/single-choice, or the exact validated coordinate12 output keys. The latter does not authorize arbitrary x/y logic-state tasks, inverse/affine contracts or new protocols. It does not infer a conceptual misconception from an incorrect scalar answer. An otherwise admitted native contract whose component mapping is not supported retains explicit unavailable coverage and zero preference; missing ranking metadata does not make valid content disappear.

The projection considers the last 20 independent observations within 60 captured local days in the exact objective/family/band, band/scoring/representation contract, language, tool and pacing group. Within that group it matches the exact reviewed structure and component ID. Two **different semantic items** missing that component since a full component success are required. A later full component success clears that component's preference; a scalar-only correction clears the structure's pending pattern as an uncertainty barrier because it supplies no corrected component authority. A new repeated pattern can be established afterward. Help, self-report, protected/transfer/personal events, semantic repeats, conflicting duplicate identities, quarantined/corrected authority and unknown conditions cannot mint this signal. Confidence and response speed are not inputs.

The resulting preference is binary, preventing a format with many output fields from acquiring arbitrary priority. It never changes the target band, automatic-change allowance, historical score, queue status or review rung. It cannot override hard constraints or the higher-priority structure-share rank.
